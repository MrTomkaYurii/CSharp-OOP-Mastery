# 01. Динамічне програмування простими словами (Algorithmic Dynamic Programming)

Багатьох студентів лякає сама назва «Динамічне програмування» (DP). Насправді за цим терміном ховається надзвичайно проста й життєва ідея:

> **Динамічне програмування — це коли ми записуємо результати вже розв'язаних маленьких підзадач у блокнот (словник або таблицю), щоб ніколи не рахувати одне й те саме двічі.**

---

## 1. Ідея «на пальцях»: чому звичайна рекурсія гальмує?

Уявіть, що на аркуші паперу написано:
`1 + 1 + 1 + 1 + 1`
Вас запитують: «Скільки тут?» Ви перераховуєте одинички і кажете: **«5»**.
Після цього дописують ще `+ 1` і питають: «А тепер скільки?»
Ви миттєво відповідаєте **«6»**, тому що **запам'ятали попередній результат (5)** і просто додали до нього `1`.

А от **наївна рекурсія без пам'яті** щоразу починає перераховувати всі одинички із самого початку!

### Приклад: Задача про сходинки (Climbing Stairs)
Уявіть сходи з $N$ сходинок. За один крок можна піднятися на **1** або на **2** сходинки. Скількома способами можна піднятися на $5$-ту сходинку?
- Потрапити на 5-ту сходинку можна лише з **4-ї** (зробивши крок на 1) або з **3-ї** (перестрибнувши через одну на 2).
- Отже: `Ways(5) = Ways(4) + Ways(3)`.

Подивіться, що робить звичайна рекурсія:
```
                          Ways(5)
                      /             \
                Ways(4)             Ways(3)
               /      \             /     \
           Ways(3)   Ways(2)    Ways(2)  Ways(1)
           /    \
       Ways(2) Ways(1)
```
Зверніть увагу: вона рахує `Ways(3)` двічі, а `Ways(2)` — тричі!
Якщо сходинок буде не 5, а **40**, то кількість однакових повторних викликів перевищить **331 мільйон**!

## 2. Два способи виправити це: Мемоізація vs Табуляція

Існує лише два підходи до динамічного програмування. Вони дають однакову відповідь, але мислять у протилежних напрямках:

| Питання | 1. Мемоізація (Top-Down / Згори-Вниз) | 2. Табуляція (Bottom-Up / Знизу-Вгору) |
| :--- | :--- | :--- |
| **Як мислимо?** | Починаємо з великої мети $N$ і рекурсивно спускаємося вниз, записуючи відповіді у блокнот (`Dictionary`). | Взагалі без рекурсії! Починаємо з нуля і заповнюємо масив `dp[0], dp[1], dp[2]...` у циклі `for`. |
| **Що у коді?** | Рекурсивна функція + `Dictionary<int, long>` | Цикл `for (int i = 2; i <= n; i++)` + масив `long[] dp` |
| **Ризик переповнення стека** | При дуже великих $N$ ($> 10\,000$) можливий `StackOverflowException`. | **Жодного ризику** — стек викликів не використовується. |
| **Економія пам'яті** | Потрібно зберігати весь словник $O(N)$. | Часто можна залишити **лише 2 змінні** (`prev1`, `prev2`) — пам'ять $O(1)$! |

### Шаблон Мемоізації (Top-Down) у 4 рядки ([01-Memoization-Basics/Program.cs](../01-Memoization-Basics/Program.cs))
```csharp
private static long CountWaysMemoized(int step, Dictionary<int, long> memo)
{
    if (step <= 2) return step; // 1. Базовий випадок

    // 2. Перевіряємо блокнот: якщо вже рахували — миттєво повертаємо!
    if (memo.TryGetValue(step, out long cached))
        return cached;

    // 3. Якщо ще не рахували — обчислюємо і записуємо у блокнот
    long result = CountWaysMemoized(step - 1, memo) + CountWaysMemoized(step - 2, memo);
    memo[step] = result;
    return result;
}
```

### Шаблон Табуляції (Bottom-Up) ([02-Tabulation-Basics/Program.cs](../02-Tabulation-Basics/Program.cs))
```csharp
long[] dp = new long[n + 1];
dp[0] = 1;
dp[1] = 1;

for (int i = 2; i <= n; i++)
{
    dp[i] = dp[i - 1] + dp[i - 2]; // Кожна наступна клітинка — сума двох попередніх
}
return dp[n];
```
А оскільки нам потрібні лише дві останні клітинки, ми можемо замінити весь масив `dp[]` на дві змінні `prev1` та `prev2`, зменшивши витрати пам'яті до $O(1)$!

## 3. Три класичні задачі з життя ([03-Classic-DP-Problems/Program.cs](../03-Classic-DP-Problems/Program.cs))

### 3.1. Кавомашина та решта монетами (Coin Change)
* **Життєва ситуація**: Кавомашині потрібно видати клієнту решту **11 грн** найменшою кількістю монет. Доступні монети: **1 грн, 2 грн, 5 грн**.
* **Як працює таблиця `dp[сума]`**:
  Ми створюємо масив `dp[0..11]`, де для кожної суми від 0 до 11 грн записуємо мінімальну кількість монет:
  - `dp[0] = 0` (для 0 грн треба 0 монет).
  - Щоб знайти відповідь для суми `i`, ми пробуємо взяти кожну монету (`1`, `2` або `5`) і дивимося у вже заповнену клітинку `dp[i - монета]`:
    $$dp[i] = \min(\text{монета} \le i) \{ dp[i - \text{монета}] + 1 \}$$
  - Для `11 грн` алгоритм знаходить оптимум: `dp[11] = dp[6] + 1 (монета 5 грн) = 3 монети` (`5 + 5 + 1`).

### 3.2. Туристичний рюкзак (0/1 Knapsack Problem)
* **Життєва ситуація**: Ви йдете в похід із рюкзаком, що витримує максимум **7 кг**. Є 4 речі:
  - Намет (4 кг, цінність 900)
  - Спальник (3 кг, цінність 700)
  - Пальник (1 кг, цінність 300)
  - Фотокамера (2 кг, цінність 500)
* **Як працює двовимірна таблиця `dp[річ, вага]`**:
  Для кожної речі і кожної місткості рюкзака $w$ від $0$ до $7$ кг ми приймаємо просте рішення з двох варіантів:
  1. **Не брати річ**: тоді цінність залишається такою ж, як у попередньому рядку `dp[i - 1, w]`.
  2. **Взяти річ** (якщо вона влазить за вагою): тоді ми отримуємо `цінність речі + найкращий результат для вільного місця, що залишилося` (`dp[i - 1, w - вага_речі]`).
  Обираємо `Math.Max` із цих двох варіантів! Для 7 кг отримуємо ідеальний набір: **Намет (4 кг) + Пальник (1 кг) + Фотокамера (2 кг) = 1700 балів**.

### 3.3. Виправлення одруківок у слові (Відстань Левенштейна)
* **Життєва ситуація**: Коли ви друкуєте з помилкою, смартфон рахує, скільки букв потрібно замінити, вставити або видалити, щоб перетворити введене слово на правильне.
* **Приклад**: Перетворити `"КІТ"` на `"КОД"`.
  Будується табличка букв $3 \times 3$:
  - `'К'` і `'К'` однакові $\to 0$ операцій;
  - `'І'` замінюємо на `'О'` $\to +1$ операція;
  - `'Т'` замінюємо на `'Д'` $\to +1$ операція.
  Разом: відстань редагування дорівнює **2 операціям**.

## 4. Патерн Generic Memoizer у C# ([04-Generic-Memoizer-Pattern/Program.cs](../04-Generic-Memoizer-Pattern/Program.cs))

У C# можна написати універсальний метод розширення `.Memoize()`, який автоматично додає потокобезпечний словник-кеш `ConcurrentDictionary` до будь-якої функції:

```csharp
public static Func<T, TResult> Memoize<T, TResult>(this Func<T, TResult> func) where T : notnull
{
    var cache = new ConcurrentDictionary<T, TResult>();
    return arg => cache.GetOrAdd(arg, func);
}
```
