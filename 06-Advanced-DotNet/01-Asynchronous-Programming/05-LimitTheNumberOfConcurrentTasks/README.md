# 05. Обмеження кількості одночасних завдань через SemaphoreSlim (LimitTheNumberOfConcurrentTasks)

## 📌 Теоретичний огляд

Хоча `Task.WhenAll` чудово підходить для паралельного запуску задач, запуск сотень або тисяч одночасних мережевих запитів призводить до проблем:
- **Database Connection Pool Exhaustion:** База даних має ліміт пулу з'єднань (наприклад, 100), і надмірні паралельні запити завершуються `TimeoutException`.
- **HTTP 429 Too Many Requests (Rate Limiting):** Зовнішні API блокують клієнта при перевищенні ліміту запитів на секунду.
- **Вичерпання сокетів та пам'яті.**

### Рішення: `SemaphoreSlim` як асинхронний дросель (Throttling)
На відміну від важкого системного `Semaphore`, `SemaphoreSlim`:
- Є легковагим об'єктом користувацького простору (user-mode).
- Підтримує **неблокуюче** очікування черги через `await semaphore.WaitAsync()`.
- Дозволяє строго контролювати ліміт паралелізму (Concurrency Limit).

```mermaid
    Free1 & Free2 & Free3 -.->|Наступні задачі з черги| Gate
```

---

## 🔍 Розрахунок часу виконання

- Всього карток: **15**
- Час обробки однієї картки: **1 секунда**
- Максимум паралельних задач: **3**
- Загальний час: `(15 / 3) * 1 сек = ~5 секунд` (замість 15 секунд при послідовному виконанні).

---

## ⚠️ Критичне правило: Блок `try-finally`

При роботі з семафором **завжди** розміщуйте `Release()` у блоці `finally`:
```csharp
await semaphore.WaitAsync();
try
{
    await DoWorkAsync();
}
finally
{
    // Якщо станеться помилка, слот НЕ зависне, а повернеться черзі!
    semaphore.Release();
}
```
Якщо пропустити `finally` і операція впаде з помилкою, лічильник семафора зменшиться назавжди, що призведе до повного зависання застосунку.

---

## 💡 Modern .NET Alternative: `Parallel.ForEachAsync` (.NET 6+)
Починаючи з .NET 6, для обробки колекції з обмеженням паралелізму існує готова конструкція:
```csharp
await Parallel.ForEachAsync(creditCards, new ParallelOptions { MaxDegreeOfParallelism = 3 }, async (card, ct) =>
{
    await ProcessCard(card);
});
```
`Parallel.ForEachAsync` під капотом виконує ту саму координацію, що й `SemaphoreSlim`, але має лаконічніший синтаксис.
