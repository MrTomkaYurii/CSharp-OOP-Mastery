# Правила та Регламент Міграції: CSharp-OOP-Mastery

Цей документ визначає суворі стандарти, правила архітектури, регламент переносу та чекліст валідації для консолідації розрізнених репозиторіїв курсу ООП у єдиний майстер-репозиторій **CSharp-OOP-Mastery**.

---

## 1. Головна мета проекту
Створити єдиний, сучасний, бездоганно структурований **освітній монорепозиторій («Живий підручник»)** з об'єктно-орієнтованого програмування та архітектури на платформі **.NET 10 (C# 13/14)**.

---

## 3. Семикроковий алгоритм міграції (The 7-Step Migration Flow)

Для кожного окремого репозиторію **суворо виконується наступний чекліст**:

### Крок 1: Аудит вхідного репозиторію (Audit & Discovery)
- [ ] Перевірити структуру вхідної папки: які проекти (`.csproj`), рішення (`.sln`), файли пояснень (`.txt`, `.md`, `.pdf`) присутні.
- [ ] Виявити криптичні або несистемні назви папок (наприклад, посилання на підручники типу `SOLIS-p074`).
- [ ] Зафіксувати ключову навчальну ідею модуля.

### Крок 2: Чисте перенесення без сміття (Clean Extraction)
- [ ] Копіювати виключно вихідний код і ресурси проекту.
- [ ] **Категорично заборонено переносити:**
  - Внутрішні каталоги `.git` та `.github`
  - Папки артефактів збірки: `bin/`, `obj/`, `out/`
  - Службові каталоги IDE: `.vs/`, `.idea/`, `.vscode/`
  - Користувацькі файли конфігурацій: `*.user`, `*.suo`

### Крок 3: Модернізація до .NET 10 (Target Framework Upgrade)
- [ ] Перевести всі проекти (`.csproj`) на `<TargetFramework>net10.0</TargetFramework>`.
- [ ] Встановити `<Nullable>enable</Nullable>` та `<ImplicitUsings>enable</ImplicitUsings>`.
- [ ] Оновити всі NuGet-пакети до актуальних стабільних версій під .NET 10 (наприклад, Microsoft.EntityFrameworkCore 10.x, Spectre.Console, AutoMapper).
- [ ] Переконатися, що синтаксис відповідає сучасному стандарту C# 13/14 (file-scoped namespaces, pattern matching, collection expressions там, де це доречно).

### Крок 4: Нормалізація структури та назв (Structure & Refactoring)
- [ ] Якщо в модулі є незрозумілі назви папок (наприклад, `SOLIS-p110`), розкласти їх за зрозумілими навчальними категоріями:
  - `01_Problem_...` — приклад проблеми / антипатерну.
  - `02_Solution_...` — вирішення з поясненням.
  - `03_Concepts_...` — демонстрація конкретних механізмів.
- [ ] Перевірити зв'язки у файлі `.sln`, щоб всі відносні шляхи до `.csproj` були коректними і рішення відкривалося у Visual Studio / Rider без помилок.

### Крок 5: Створення / актуалізація навчального посібника (README.md)
У кожній темі обов'язково має бути якісний `README.md` українською мовою за еталонним стандартом (як у розділі SOLID):
1. **Заголовок та концепція:** що вивчаємо і навіщо це потрібно в реальній розробці.
2. **Навігаційна таблиця:** список проектів, їхнє призначення, файли швидкого переходу.
3. **Порівняльний аналіз (Bad vs Good):**
   - «Як не треба» (типові антипатерни).
   - «Як правильно» (канонічна архітектура).
4. **Архітектурна діаграма Mermaid:** візуалізація класів або послідовності викликів.
5. **Нюанси та підводні камені .NET:** практичні поради інженеру.

### Крок 6: Верифікація збірки та тестів (Build Verification)
- [ ] Виконати тестову компіляцію модуля через команду:
  `dotnet build <PathToSolutionOrProject> -c Release`
- [ ] Переконатися: **0 помилок збірки (0 Errors)**.
- [ ] Усунути будь-які несумісності API або попередження компілятора.

### Крок 7: Атомарний коміт та оновлення трекера (Commit & Track)
- [ ] Зафіксувати зміни чітким коммітом за стандартом Conventional Commits:
  `feat(<module>): migrate and modernize <TopicName> to .NET 10 with docs`
- [ ] Оновити статус у файлі `MIGRATION_TRACKER.md`.

## 5. Безпека даних
1. **Оригінальні папки не видаляються під час міграції.**
2. Новий монорепозиторій формується паралельно в ізольованій папці `CSharp-OOP-Mastery`.
