# Лекція 2: Явна Реалізація Інтерфейсів (Explicit Interface Implementation)

У мові C# інтерфейс можна реалізувати двома способами: **неявно (Implicit)** та **явно (Explicit)**.

---

## 1. Проблема однакових імен у різних інтерфейсах

Уявімо клас `UserForm`, який реалізує два інтерфейси від різних розробників:
```csharp
public interface IWindow { void Close(); }
public interface IFile   { void Close(); }
```
Якщо написати звичайний `public void Close()`, один і той самий метод закриватиме і вікно, і файл, що логічно є помилкою.

---

## 2. Як працює явна реалізація (`Explicit`)

При явній реалізації ім'я інтерфейсу вказується безпосередньо перед ім'ям методу, а модифікатор доступу `public` **опускається**:

```csharp
public class UserForm : IWindow, IFile
{
    // Явна реалізація IWindow:
    void IWindow.Close()
    {
        Console.WriteLine("Вікно графічного інтерфейсу закрито.");
    }

    // Явна реалізація IFile:
    void IFile.Close()
    {
        Console.WriteLine("Файловий дескриптор скинуто на диск і закрито.");
    }
}
```

### Як викликати такі методи?
Явно реалізовані методи **НЕ є публічними членами класу**! Вони доступні лише тоді, коли об'єкт приведено до відповідного інтерфейсу:

```csharp
UserForm form = new UserForm();

// form.Close(); // ❌ Помилка компіляції! У класі UserForm немає публічного методу Close

// Виклик через інтерфейсні посилання:
IWindow win = form;
win.Close(); // ➔ "Вікно графічного інтерфейсу закрито."

IFile file = form;
file.Close(); // ➔ "Файловий дескриптор скинуто на диск і закрито."
```

---

## 3. Коли застосовувати явну реалізацію?
1. **Вирішення конфліктів сигнатур:** коли кілька інтерфейсів вимагають метод з однаковим ім'ям і параметрами.
2. **Приховування технічних або службових методів:** щоб публічний API класу залишався лаконічним і чистим.
3. **Реалізація застарілих або нетипізованих інтерфейсів BCL:** наприклад, `IEnumerable` (нетипізований) завжди реалізується явно поруч з `IEnumerable<T>`.
