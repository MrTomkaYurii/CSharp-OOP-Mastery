# Лекція 01: Базове спадкування, Розміщення полів у Пам'яті та Конструктори (`base` і `this`)

**Успадкування (Inheritance)** — це фундаментальний механізм ООП, який дозволяє створити новий спеціалізований клас (**похідний / `derived class`**) на основі вже існуючого (**базового / `base class`**). Похідний клас автоматично переймає всі поля, властивості та методи базового класу (окрім конструкторів і фіналізаторів), додаючи власний стан або розширюючи поведінку.

---

## 1. Семантика `IS-A` та Розміщення Похідного Об'єкта в Купі CLR

Відношення між похідним і базовим класом описується правилом **«IS-A» («Є різновидом»)**: `Manager` **є** `Employee`, `Dog` **є** `Animal`. У C# підтримується **одиночне спадкування класів (Single Implementation Inheritance)**: клас може мати лише один безпосередній базовий клас, а коренем усієї ієрархії завжди виступає `System.Object`.

Коли ми створюємо екземпляр похідного класу `new OtherClass()` (`SOLIS-p177`), середовище CLR виділяє в керованій купі **єдиний неперервний блок пам'яті**, який містить спочатку всі поля базового класу (`SomeClass`), а одразу за ними — поля похідного класу (`OtherClass`):

```mermaid
flowchart LR
    subgraph Stack ["Стек потоку (Stack)"]
        ocRef["oc (Посилання OtherClass)\nАдреса: 0x0400"]
    end

    subgraph Heap ["Єдиний об'єкт OtherClass у Купі (0x0400)"]
        direction TB
        hdr["ObjectHeader + MethodTablePtr (OtherClass)"]
        basePart["Частина базового класу (SomeClass):\nField1 = 'Базове поле 1'\nField2 = 'Базове поле 2'"]
        derivedPart["Частина похідного класу (OtherClass):\nField3 = 'Похідне поле 3'\nField4 = 'Похідне поле 4'"]
        hdr --- basePart --- derivedPart
    end

    ocRef -->|"Вказує на початок об'єкта"| hdr
```

> [!NOTE]
> Навіть якщо поле базового класу оголошене як `private`, воно **фізично присутнє** всередині пам'яті кожного екземпляра похідного класу (просто компілятор не дозволяє звертатися до нього напряму з коду спадкоємця без публічних або захищених методів базового класу).

## 2. Маскування членів (`new`) та Доступ до базового класу (`base.Field`)

Що відбувається, якщо в похідному класі оголосити поле або метод із тим самим іменем, яке вже існує в базовому класі (`SOLIS-p180`, `SOLIS-p181`)?
1. Компілятор видасть попередження `CS0108` («член приховує успадкований член»), якщо ми явно не вкажемо ключове слово **`new`**, яке підтверджує, що **приховування (hiding / masking)** зроблено свідомо.
2. При цьому старе поле базового класу **не зникає**! В об'єкті в купі тепер існують **два окремі поля** з однаковим коротшим ім'ям: `SomeClass.Field1` та `OtherClass.Field1`.
3. Щоб звернутися з методу похідного класу саме до прихованого члена базового класу, використовується префікс **`base.`** (`SOLIS-p181`):

```csharp
class SomeClass
{
    public string Field1 = "Field1 — значення з базового класу (SomeClass)";
}

class OtherClass : SomeClass
{
    // Модифікатор 'new' явно маскує базове поле Field1 власним полем похідного класу:
    new public string Field1 = "Field1 — нове значення у похідному класі (OtherClass)";

    public void PrintBothFields()
    {
        Console.WriteLine(Field1);      // Читає this.Field1 (з OtherClass)
        Console.WriteLine(base.Field1); // Читає приховане поле з базової частини (SomeClass)
    }
}
```

## 3. Порядок виконання Конструкторів в Ієрархії (`: base(...)` та `: this(...)`)

Конструктори **не успадковуються** похідними класами, але базова частина об'єкта зобов'язана бути коректно проініціалізованою перед тим, як почне працювати код конструктора спадкоємця (`SOLIS-p196`).

Тому при виклику `new DerivedClass(...)` ініціалізація відбувається у суворій послідовності:

```mermaid
flowchart TD
    Step1["1. Виділення пам'яті в Купі під УСІ поля (Object + Base + Derived)\nта занулення байтів за замовчуванням"]
    Step2["2. Виконання ініціалізаторів полів при оголошенні у DerivedClass"]
    Step3["3. Виконання ініціалізаторів полів при оголошенні у BaseClass"]
    Step4["4. Виконання тіла конструктора System.Object -> BaseClass (: base(...))"]
    Step5["5. Виконання тіла конструктора похідного класу (DerivedClass)"]

    Step1 --> Step2 --> Step3 --> Step4 --> Step5
```

### Порівняння `: base(...)` та `: this(...)` (`SOLIS-p196` та `Ex-ThisInConstructor`):

| Синтаксис | Куди передає керування | Типовий сценарій використання |
|:---|:---|:---|
| **`: base(args)`** | Викликає обраний конструктор **безпосереднього базового класу** | Передача обов'язкових параметрів (наприклад, `id`, `userName`), які зберігаються у базовому класі (`SOLIS-p196`) |
| **`: this(args)`** | Викликає інший перевантажений конструктор **цього ж самого класу** | Усунення дублювання коду ініціалізації (Constructor Chaining — вузькі конструктори делегують роботу головному конструктору, див. `Ex-ThisInConstructor`) |

```csharp
public class Employee
{
    public string FullName { get; }
    public Employee(string fullName) => FullName = fullName;
}

public class Manager : Employee
{
    public string Department { get; }
    public int TeamSize { get; }

    // 1. Головний конструктор передає ім'я в базовий клас через : base(fullName)
    public Manager(string fullName, string department, int teamSize)
        : base(fullName)
    {
        Department = department;
        TeamSize = teamSize;
    }

    // 2. Перевантажений конструктор делегує роботу головному конструктору через : this(...)
    public Manager(string fullName, string department)
        : this(fullName, department, teamSize: 5)
    {
    }
}
```

> [!WARNING]
> Якщо базовий клас має лише конструктор із параметрами (і не має конструктора без параметрів `Base()`), то похідний клас **зобов'язаний** явно викликати `: base(...)` у своїх конструкторах, інакше виникне помилка компіляції `CS7036`.
