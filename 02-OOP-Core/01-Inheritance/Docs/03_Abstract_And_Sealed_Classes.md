# Лекція 3: Абстрактні Класи, Контракти та Модифікатор `sealed`

## 1. Абстрактні Класи (`abstract class`)

**Абстрактний клас** — це неповний клас, призначений виключно для використання в ролі базового. Він представляє незавершений каркас або концепцію:
* Не можна створити екземпляр через `new Shape()`.
* Може містити як звичайні методи з реалізацією, так і **абстрактні методи** (`abstract methods`).

### Абстрактний метод:
* Не має тіла `{ ... }`.
* Автоматично є віртуальним.
* Будь-який неабстрактний похідний клас **зобов'язаний** надати його реалізацію через `override`.

```csharp
public abstract class Shape
{
    public string Name { get; }
    protected Shape(string name) => Name = name;

    // Абстрактний метод: похідний клас ЗОБОВ'ЯЗАНИЙ його реалізувати
    public abstract double CalculateArea();

    // Звичайний конкретний метод: спільна логіка для всіх фігур
    public void PrintInfo() => Console.WriteLine($"{Name}: Площа = {CalculateArea()}");
}
```

## 2. Запечатані Класи та Методи (`sealed`)

Модифікатор **`sealed`** забороняє подальше успадкування від класу або перевизначення конкретного віртуального методу:

```csharp
public sealed class SecurityTokenManager { ... } // Успадкуватися від цього класу неможливо!
```

### Чому `sealed` важливий у сучасному високопродуктивному .NET 10?
1. **Архітектурна безпека:** Гарантує, що інваріанти класу не будуть спотворені невідомими підкласами.
2. **Девіртуалізація компілятором JIT (Devirtualization):**  
   Коли JIT-компілятор бачить виклик методу на запечатаному типі (`sealed`), він знає, що похідних класів не існує в природі. JIT замінює дорогий виклик через таблицю віртуальних методів (`callvirt`) на прямий блискавичний виклик (`call`) або навіть інлайнить тіло методу напряму!
