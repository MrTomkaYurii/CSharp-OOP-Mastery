# Лекція 2: Обмеження Параметрів Типу (`where Constraints`)

За замовчуванням компілятор не знає нічого про невідомий тип `T`, окрім того, що він успадковує `System.Object`. Відповідно, над змінною типу `T` можна викликати лише методи `ToString()`, `Equals()`, `GetHashCode()`.

Щоб дозволити виклики специфічних методів, створення об'єктів через `new()` чи операції порівняння, застосовують **обмеження типів (`where`)**.

---

## 1. Повний довідник обмежень `where` у .NET 10

| Обмеження | Опис | Що дозволяє в коді? |
|:---|:---|:---|
| `where T : struct` | Тип **зобов'язаний бути значущим** (Value Type, окрім `Nullable<T>`) | Гарантує розміщення в стеці, відсутність `null` |
| `where T : class` | Тип **зобов'язаний бути посилальним** (Reference Type) | Можна порівнювати з `null`, приводити до `null` |
| `where T : notnull` | Тип не може приймати `null` (діє для C# 8+ Nullable Reference Types) | Запобігає передачі `null` для структур або класів |
| `where T : new()` | Тип зобов'язаний мати **публічний конструктор без параметрів** | Дозволяє писати `T item = new T();` |
| `where T : BaseClass` | `T` має бути цим класом або його похідним | Дозволяє звертатися до публічних членів `BaseClass` |
| `where T : ISomeInterface` | `T` має реалізовувати даний інтерфейс | Дозволяє викликати контрактні методи інтерфейсу |
| `where T : unmanaged` | Тип має бути некерованою структурою (без полів-посилань) | Дозволяє пряму роботу з вказівниками та пам'яттю |

---

## 2. Практичні комбінації обмежень

```csharp
// Репозиторій сутностей з ідентифікатором та конструктором:
public class Repository<T> where T : class, IEntity, new()
{
    public T CreateAndSave(int id)
    {
        T entity = new T(); // Можливо завдяки 'new()'
        entity.Id = id;     // Можливо завдяки 'IEntity'
        SaveToDatabase(entity);
        return entity;
    }
}
```

> [!WARNING]
> Якщо використовується конструкція `new()`, вона **завжди має стояти останньою** у списку обмежень для конкретного параметра типу.
